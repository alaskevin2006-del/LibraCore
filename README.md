# LibraCore｜图书馆管理系统

LibraCore 是软件工程初级实训课程的四人小组项目，目标是开发一套支持**读者端**与**管理员端**的图书管理系统。项目优先保证核心业务正确、数据一致和可演示，再逐步完善用户体验、测试与扩展功能。

> **项目状态：** 初始化与基础架构搭建阶段。本文描述的是当前规划，**不代表相关功能已经实现**。

## 1. 项目目标

计划实现以下核心功能：

- **读者端：** 图书查询、借阅与归还、个人借阅记录查询。
- **管理员端：** 图书信息管理、读者信息管理、借还记录管理。
- **系统能力：** 角色权限校验、业务异常处理、数据持久化与一致性验证。

扩展方向包括多终端数据共享、借阅统计、批量导入导出和超期提醒；续借、预约与 Android 客户端暂不列为基础交付要求，是否实施以阶段验收和团队决议为准。

## 2. 技术方案

| 部分 | 计划采用的技术 |
| --- | --- |
| Windows 客户端 | C++17、Qt 6、QML / Qt Quick、Qt Network |
| 后端服务 | C++17、Drogon、REST API |
| 数据库 | MySQL 8 |
| 接口通信 | HTTPS、JSON、OpenAPI |
| 构建及协作 | CMake、Git、GitHub |
| 云端部署 | Ubuntu、Docker Compose、反向代理与 TLS |

计划的数据链路：

```text
Qt 客户端 → HTTPS/JSON → 反向代理 → Drogon 后端 → MySQL
```

MySQL 不直接向公网开放。云端部署应使用独立的容器、网络、数据卷及配置，避免影响服务器上的其他项目。

## 5. 开发协作约定

目前规划使用以下分支：

- `main`：经审核、集成和验证的稳定版本。
- `lkx`、`dhw`、`hyq`、`zyj`：各成员的开发分支。

建议流程：

1. 从最新的 `main` 同步代码，在本人分支或任务分支开展开发。
2. 完成一项功能后提交 Commit，并推送到 GitHub。
3. 创建指向 `main` 的 Pull Request（PR），写明修改内容、关联任务及测试结果。
4. 由其他成员审核；涉及公共接口时，同时更新 `api/openapi.yaml` 并通知调用方。
5. 审核和必要的测试通过后再合并到 `main`。

**注意：分支本身不构成权限隔离。** `main` 的保护规则、PR 审核及自动化检查应由仓库管理员在 GitHub 中单独配置；配置完成前不得视为已受保护。
