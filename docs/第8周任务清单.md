# LibraCore｜第8周详细任务清单

**周期：** 2026年10月26日（周一）—11月1日（周日）  
**正式验收：** 2026年11月2日（周一）  
**范围说明：** 以下是小组第8周的自定开发任务，不是老师另行规定的交付要求。仓库具体路径以现有工程结构为准。

## 0. 本周共同目标与边界

**唯一核心里程碑 M1：** Qt 客户端发起图书查询 → 公网 Drogon API → MySQL 查询真实数据 → Qt 页面显示。

- **必须完成：** 后端真实查询、基础数据库及测试数据、读者端真实查询、管理员端真实图书列表、基本联调与记录。
- **本周提前做：** 管理端新增/编辑/删除的页面交互和输入校验，允许使用 Mock（模拟）数据。
- **本周不做：** 真实登录鉴权、真实新增/编辑/删除入库、完整借还、统计、Android。
- **API 原则：** lkx 先发布只覆盖本周查询功能的 v0.1；其余接口根据后续需求每周补充，避免过度设计。

## 1. 每个人的任务与交付物

### lkx｜后端、API、服务器

- [ ] **L1 接口契约（周二前争取发布）**：与 zyj 确认图书字段，与 dhw、hyq 确认页面最小所需数据；确定 `GET /health`、`GET /api/books` 的地址、查询参数（是否支持 `keyword`）、成功/失败 JSON 样例。**交付：** API 规范 v0.1。**验收：** 三人能够照规范开发，不再自行猜字段。
- [ ] **L2 后端骨架**：建立 Drogon 可编译工程，划清 Controller（接请求）与 Repository（查库）的调用边界；实现 `/health`。**交付：** 后端源码。**验收：** 服务启动且健康检查有明确响应。
- [ ] **L3 图书查询 API**：先用固定示例响应验证路由，随后接入 zyj 的 Repository，返回实际 MySQL 数据；异常时返回明确错误。**交付：** `GET /api/books`。**验收：** HTTP 请求返回数据库中的图书，不是写死的数组。
- [ ] **L4 服务器部署与隔离**：为 LibraCore 使用独立部署目录、配置、服务/容器和数据存储，避免影响服务器上已有项目；配置公网入口与 HTTPS，MySQL 不直接暴露公网，账号和密码不入库。**交付：** 部署配置与说明。**验收：** 外部机器可访问 API，原有项目仍正常。
- [ ] **L5 联调与记录**：与 zyj 测数据库查询，与 dhw 测 Qt 的真实请求；保存成功响应、故障定位及部署说明。**交付：** 接口测试与联调记录、PR。**验收：** 端到端返回真实数据。

**交给别人的关键东西：** 尽早给全员 API 字段/样例；给 dhw 可访问地址；接收 zyj 的查询函数并完成后端集成。

### zyj｜数据库设计、SQL、Repository

- [ ] **Z1 数据库模型**：设计 `users`（用户）、`books`（书目）、`book_copies`（馆藏副本）、`borrow_records`（借阅记录）四类实体，明确主键、外键及“同一书目可有多本副本”。**交付：** ER 图、数据字典初稿。**验收：** 能说明每张表负责什么以及表之间怎样关联。
- [ ] **Z2 可执行建表脚本**：编写 `schema.sql`，使用统一字段、类型、主外键等约束；先在独立测试库执行。**交付：** 建表脚本。**验收：** 从空测试库能建表，结构与数据字典相符。
- [ ] **Z3 测试数据**：编写 `seed.sql`，生成/插入约 10—20 条模拟书目、必要的馆藏副本及少量虚构用户；保证关联关系正确，说明脚本如何运行。**交付：** 测试数据脚本。**验收：** 执行后可 `SELECT` 查到数据，不使用真实学生资料。
- [ ] **Z4 图书查询 Repository**：先与 lkx 约定函数签名、返回类型和图书字段，再实现从 MySQL 读取图书数据的查询模块；若支持关键词，使用参数化查询。**交付：** 可集成的 Repository 源码。**验收：** 被 lkx 的 API 调用后返回真实数据，不在 Controller 内重复写 SQL。
- [ ] **Z5 数据验证**：测试建表、插数、查询；重启数据库再查；记录失败情况和修复。**交付：** SQL 运行结果、简单测试记录、PR。**验收：** 初始化步骤可复现，重启后数据仍在。

**交给别人的关键东西：** 尽早给 lkx `books` 相关字段和查询函数约定；交付脚本及 Repository 后，与 lkx 在服务器测试库验证部署。**分工边界：** zyj 写并先验证 SQL，lkx 负责将审核后的脚本部署到服务器；两人共同维护实际结构与仓库脚本一致。

### dhw｜Qt 公共工程、网络模块、读者页面

- [ ] **D1 客户端公共工程**：提供 Qt/C++/QML 主工程、读者/管理页面入口以及约定的页面文件组织方式；尽早通知 hyq。**交付：** 可运行的客户端公共工程。**验收：** hyq 的页面能接入同一个项目。
- [ ] **D2 公共网络模块**：按 lkx 的 API v0.1 实现异步 GET、JSON 解析以及请求成功/失败的传递；服务端地址集中配置，不写死在各个页面。**交付：** 可复用的网络模块及调用示例。**验收：** 读者端和管理端可复用同一个请求入口。
- [ ] **D3 读者查询页**：实现查询输入框、按钮、图书列表、点击查看基本详情；包含加载中、空结果及失败提示。可先用 Mock 测交互。**交付：** 页面源码。**验收：** 页面操作完整，能显示接口约定字段。
- [ ] **D4 真实接口联调**：连接 lkx 的公网 API；确认搜索/列表结果与 MySQL 一致，模拟断网时页面不假报成功。**交付：** 可运行读者端、运行截图/录屏。**验收：** 点击按钮看到真实图书结果。
- [ ] **D5 前端共享与提交流程**：给 hyq 网络模块调用说明，完成个人分支提交和 PR，附简短运行方法。**交付：** 使用说明、PR、简单测试记录。

**交给别人的关键东西：** 尽早给 hyq Qt 工程结构、可调用的网络模块接口；向 lkx 反馈请求字段与错误状态需求。

### hyq｜管理员图书管理页面

- [ ] **H1 页面结构与对接**：和 dhw 确定管理员页面在同一 Qt 工程中的接入方式，按 lkx API v0.1 确认列表字段。**交付：** 管理员页面模块。**验收：** 能被客户端主工程打开。
- [ ] **H2 图书列表**：实现图书列表显示、空列表/加载中/失败提示；先用 Mock，后调用 dhw 的网络模块显示真实数据。**交付：** 图书列表页面。**验收：** 显示真实服务端数据，而非只截图。
- [ ] **H3 提前完成管理交互**：新增弹窗、编辑弹窗、删除确认，填写表单并完成基本校验（如书名不能为空）；增删改操作仅更新 Mock 数据。**交付：** 可操作的管理端界面源码。**验收：** 能完整演示模拟新增/编辑/删除，明确标注尚未持久化。
- [ ] **H4 接入与自测**：与 dhw 联调公共网络模块，与 zyj 核对字段；测试空数据、非法输入及删除取消。**交付：** 测试记录、页面截图、个人 PR。**验收：** 正常与异常交互均有明确反馈。

**交给别人的关键东西：** 尽早向 dhw 反馈所需列表字段和模块调用需求；真实数据查询只复用公共网络层，不单独再写一套。

## 2. 关键依赖和对接顺序

1. **先定契约（最晚周二初版）**：lkx + zyj 定数据字段；lkx + dhw + hyq 定 HTTP/JSON；dhw + hyq 定 Qt 公共模块调用方式。
2. **并行编码（周二—周四）**：zyj 建库和 Repository；lkx 写 Controller、部署服务；dhw 写网络模块及读者页面；hyq 写管理端 Mock 交互。谁也不必等完整项目完成才开始。
3. **分层联调（模块一旦可用就进行）**：`zyj Repository → lkx API → dhw 网络模块 → dhw/hyq 页面`。这里是联调依赖，不是四个人开始工作的先后顺序。
4. **字段变更**：先在 API/数据字典统一，再通知调用方修改；不要口头改完各自实现。
