# 图书馆管理系统｜评分标准逐项开发与验收清单

> 版本：v1.0｜整理日期：2026-10-25  
> 核心依据：《软件工程初级实训课程项目作业考核评分方案（图书管理）(1).pptx》（更新版）  
> 报告格式补充依据：《大作业开发报告基本格式.pptx》  
> 目的：开发时逐项落实；阶段验收和最终答辩前逐项检查，尽可能避免遗漏评分点。

## 0. 使用规则与开发边界

**标注说明**
- **【课程要求】**：更新版 PPT 明确提出的项目、交付或考查要求。
- **【评分示例】**：PPT 提供的图书馆业务或创新举例；原文明确说明业务例子“不代表项目需要按照下述例子严格设计”，创新功能也“不要求数量多”。为争取完整覆盖评分点，本项目将其中的高价值示例纳入自身验收范围。
- **【验收细化】**：把教师的定性要求转换为可操作的验证方法，不是教师额外规定的新功能。
- **【自选进阶】**：PPT 明示的创新方向，依实际进度选择；**手机端最后做**。

**范围原则**：仅围绕 PPT 指定或举例的功能展开，不新增座位预约、智能扫码等 PPT 未提及的业务功能。联网采用既定的 C++ + Qt 客户端 / Drogon 后端 / MySQL 云端架构，**从最早的系统骨架就接入**，但独立网络服务在课程上属于进阶内容而非必需项。技术复杂度不直接等于高分。

### 0.1 项目基本条件（新版 PPT 第 1、7 页）
- [ ] 四人小组按计划完成开发（符合原则上四人组队的要求）。
- [ ] 使用 Qt 平台开发《图书管理系统》。
- [ ] 使用 MySQL、SQLite 或 Access 中的一种数据库（本组采用 MySQL）。
- [ ] 读者侧与管理员侧功能均能够实际运行。

**建议的证据保留方式**：每项验收至少对应一次可复现演示或测试，以及必要的截图、测试结果、Git 记录、文档链接。仓库可设 `docs/`、`tests/`、`deploy/` 等目录，具体命名由小组统一。

## 1. 业务功能与完成度（30 分）

> 来源：新版评分 PPT 第 3 页。以下分项及分值为教师提供的**评分示例**，项目将其作为基础功能验收目标。

### 1.1 图书信息管理（示例 8 分）
- [ ] 支持新增图书信息。
- [ ] 支持修改已有图书信息。
- [ ] 支持删除图书信息；有引用关系时处理方式正确。
- [ ] 支持查询图书信息，查询结果与数据库一致。

**验收证据**：新增、修改、删除、查询的操作演示/测试记录。

### 1.2 借阅用户管理（示例 5 分）
- [ ] 能够管理读者信息。
- [ ] 能够查看指定读者的借阅情况。

**验收证据**：读者信息管理界面及借阅记录关联查询结果。

### 1.3 图书借阅与归还（示例 10 分）
- [ ] 能够完成图书借阅。
- [ ] 能够完成图书归还。
- [ ] 能够查看借阅记录，记录反映实际借还状态。

**验收证据**：同一图书完成“可借→借出→归还”的完整流程，数据库记录同步变化。

### 1.4 客户端与后台管理端（示例 5 分）
- [ ] 借书人可以使用读者侧功能。
- [ ] 管理员可以使用后台管理功能。
- [ ] 不同角色的可见操作与实际权限相匹配。【验收细化】

**验收证据**：读者、管理员分别登录并演示；读者无权执行管理操作。

### 1.5 业务异常处理（示例 2 分）
- [ ] 已借出的实体图书不会被重复借出。
- [ ] 借阅失败时给出合理、明确的提示。
- [ ] 对无效图书、无效用户、重复还书等情况有合理处理。【验收细化】

**验收证据**：异常测试用例及提示截图。

## 2. 技术实现与技术深度（20 分）

> 来源：新版评分 PPT 第 3 页。重点是技术合理性，不是技术堆砌。

### 2.1 Qt 技术应用（6 分）
- [ ] 正确使用 Qt 界面组件。
- [ ] 正确使用信号与槽等 Qt 交互机制。
- [ ] 界面操作、数据更新和结果反馈能够正常联动。【验收细化】

**验收证据**：Qt/QML 组件实现示例、关键交互代码和现场演示。

### 2.2 系统架构与模块划分（6 分）
- [ ] 合理区分界面模块、业务逻辑模块、数据访问模块。
- [ ] 避免将所有逻辑堆在单个文件中。
- [ ] 模块职责明确，可以独立修改与联调。【验收细化】

**验收证据**：项目目录、架构图、代表性模块代码。

### 2.3 关键技术实现（4 分）
- [ ] 数据库交互正确。
- [ ] 借阅等业务状态管理正确。
- [ ] 客户端、业务模块及数据层之间的数据传递正确。

**验收证据**：一次端到端操作的调用链说明及运行结果。

### 2.4 代码质量与可维护性（4 分）
- [ ] 命名规范统一、含义清晰。
- [ ] 代码组织清晰、易于理解。
- [ ] 公共逻辑合理复用，修改某个模块不会无故破坏其他模块。【验收细化】

**验收证据**：代码仓库、代码审查记录、代表性实现说明。

## 3. 数据库设计与数据处理（15 分）

> 来源：新版评分 PPT 第 4 页。

### 3.1 数据库表结构设计（5 分）
- [ ] 图书、用户、借阅记录等核心表设计合理。
- [ ] 字段定义清晰。
- [ ] 表之间的关联关系清晰。

**验收证据**：ER 图、数据字典、建表 SQL。

### 3.2 数据存储与查询（4 分）
- [ ] 数据能够正确新增、修改、删除、查询。
- [ ] 关闭客户端或重新启动系统后，数据仍然存在。

**验收证据**：重启前后的持久化检查、数据库查询记录。

### 3.3 数据一致性与完整性（4 分）
- [ ] 借阅状态、库存数量、借阅记录相互一致。
- [ ] 对关键业务字段进行必要的数据校验。
- [ ] 借阅冲突或操作失败时不会留下不一致的部分更新。【验收细化】

**验收证据**：成功、失败及重复借阅测试；事务执行后数据库状态核对。

### 3.4 数据库初始化与配置（2 分）
- [ ] 数据库可按说明正确初始化。
- [ ] 提供必要的数据库配置或建表说明。
- [ ] 在新的开发/验收环境中能够复现初始化流程。【验收细化】

**验收证据**：建表脚本、初始化说明、全新环境初始化验证。

**验收证据**：正常与异常操作演示、反馈截图。

## 5. 系统稳定性与测试（10 分）

> 来源：新版评分 PPT 第 4 页。

### 5.1 主要业务流程测试（4 分）
- [ ] 图书新增测试通过。
- [ ] 图书查询测试通过。
- [ ] 图书借阅测试通过。
- [ ] 图书归还测试通过。
- [ ] 关键业务的前后端联调测试通过。【验收细化】

**验收证据**：测试用例、预期结果、实际结果及执行记录。

### 5.2 异常场景与运行稳定性（4 分）
- [ ] 错误输入得到正确处理。
- [ ] 重复操作得到正确处理。
- [ ] 数据库连接失败时，系统能给出合理反馈，不产生错误业务数据。
- [ ] 常规操作中系统运行稳定。

**验收证据**：异常测试记录、错误提示截图、必要的运行日志。

### 5.3 测试记录与问题修复（2 分）
- [ ] 保留必要的测试用例。
- [ ] 保留运行截图或测试执行记录。
- [ ] 记录发现的问题及修复情况。

**验收证据**：测试报告、Bug/Issue、修复提交及回归测试结果。

> 【可选验收细化】使用脚本模拟多用户访问、并发借阅冲突。适合作为上述业务正确性与稳定性的额外证据；PPT **没有要求达到特定并发量**，无需为了高并发指标额外建设复杂基础设施。

## 7. 创新性与实用性（5 分）

> 来源：新版评分 PPT 第 5 页。教师评分关注：**有实际价值（3 分）+ 能有效运行且合理集成（2 分）**。以下是 PPT 列出的创新**示例**，并非需要全部实现；没有逐项累加的独立加分承诺。

### 7.1 创新结果的共同验收条件
- [ ] 至少选定一项超出基础功能、符合真实使用需求的创新或改进。【项目自定目标】
- [ ] 能解释该功能解决的实际问题。
- [ ] 功能真实运行，并与已有图书管理业务合理结合。
- [ ] 有演示步骤和测试证据。

### 7.2 PPT 内创新候选（按开发优先级，而非老师的固定分配）

| 顺序 | PPT 提及的候选方向 | 项目安排 | 验收内容 |
|---|---|---|---|
| 1 | **网络实现多终端数据共享** | **联网架构从 P0 开始** | 两个客户端访问同一后端，更新数据可相互查询 |
| 2 | **借阅统计 / 可视化统计分析** | 核心业务稳定后优先做 | 统计值可与数据库核对，图表显示正确 |
| 3 | **批量导入导出图书信息** | 视时间择优完成 | 导入校验、导出结果、错误处理正确 |
| 4 | **图书超期提醒** | 视时间择优完成 | 逾期条件正确，提示有效 |
| 5 | **图书分类推荐** | 可选，不优先 | 推荐逻辑明确，结果符合既定规则 |
| 6 | **手机端图书检索与借阅** | **全部其他目标完成后最后实施** | Android 能安装运行、检索及借阅，与服务端数据一致 |

- [ ] 明确最终实际采用的创新功能及其验证证据。
- [ ] 不因追求创新功能而牺牲基础功能和稳定性。

**明确不纳入当前范围**：座位预约、智能扫码借阅、复杂 AI 推荐、大规模分布式架构等非本次 PPT 必要内容。

## 9. 分阶段验收顺序（符合小组现有安排）

| 阶段 | 交付与验收重点 | 对应评分项 |
|---|---|---|
| **P0-A：基础架构** | Qt 客户端、Drogon 服务、MySQL、联网最小闭环；架构图和数据库初稿 | 2、3、6、7（联网） |
| **P0-B：核心业务** | 图书管理、读者管理、借还书、角色区分、异常处理 | 1、2、3、4 |
| **P0-C：质量验收** | 业务测试、异常测试、持久化/一致性验证、代码整合、修复记录、界面完善 | 2、3、4、5、6 |
| **P1：PPT 内实用创新** | 先完善联网共享证据，再选做统计可视化、批量导入导出、超期提醒等 | 7，并支撑 3、4、5 |
| **P2：Android（最后）** | 在上述目标通过后再打包、适配并验证手机端检索和借阅 | 7 |
| **最终交付** | 完整项目、源码、数据库说明、开发报告、至少两次组会记录、演示及答辩 | 所有维度 |

**阶段门槛**：必须先证明上一阶段功能正确、稳定并留有必要证据，才继续追加下一阶段功能。Android 是最后的可选进阶目标；即使不做，也不意味着其他评分点缺失。

## 10. 最终逐项复核

- [ ] 业务功能与完成度：各子项已完成、已演示、已有证据。
- [ ] 技术实现与技术深度：Qt 应用、架构、关键技术、代码质量均可说明。
- [ ] 数据库设计与数据处理：结构、持久化、一致性、初始化均已验证。
- [ ] 界面设计与用户体验：布局、风格、反馈全部通过检查。
- [ ] 系统稳定性与测试：主流程、异常、修复记录完整。
- [ ] 团队协作与开发过程：分工、联调、开发记录完整。
- [ ] 创新性与实用性：选做功能有效、可用、已集成并可展示。
- [ ] 项目程序、源码、数据库说明及必要文档全部齐备。
- [ ] 开发报告与至少两次组会纪要齐备。
- [ ] 完成一次模拟答辩，四名成员均能介绍相关工作。

**判断原则**：本清单覆盖新版 PPT 列出的全部评分维度及其示例，但**逐项完成并不自动保证满分**；最终评分仍取决于教师对正确性、合理性、完成质量和现场答辩的评价。
