# 图书馆管理系统技术路线与分阶段实施方案

## 一、项目目标

以真实可部署的图书馆管理系统为目标，采用 **C++ 全栈、前后端分离、模块化单体架构**。

开发优先级：**P0 课程基础功能及联网 → P1 教师推荐进阶功能 → P2 真实场景扩展**。

核心代码由组员自主开发，AI Agent 主要辅助学习、代码审查与测试。

## 二、技术架构

| 层次 | 技术选型 | 主要职责 |
|---|---|---|
| 客户端 | C++、Qt 6、QML | Windows / Android 界面及交互 |
| 网络通信 | HTTPS、REST API、JSON | 前后端数据交换 |
| 业务后端 | C++17、Drogon | 业务逻辑、认证、权限、并发控制 |
| 数据库 | MySQL | 业务数据、事务、持久化 |
| 服务器 | Ubuntu、Docker Compose、Nginx | 服务部署、反向代理、HTTPS |
| 工程协作 | Git、GitHub、CMake | 版本管理、构建、协作 |
| 自动化测试 | GoogleTest、Qt Quick Test、k6 | 单元、界面、并发及压力测试 |
| 持续集成 | GitHub Actions | 自动构建、测试、保存结果 |

客户端不直接访问数据库，所有业务操作经过后端 API。

## 三、分阶段开发

### P0：基础系统与网络化（必须完成）

| 子阶段 | 功能任务 | 需要学习的技术 | 交付成果 |
|---|---|---|---|
| 0.1 工程搭建 | Git 仓库、项目结构、编译环境 | Git、CMake、Qt Creator、Drogon | 前后端独立运行 |
| 0.2 联网贯通 | Qt 请求后端，后端访问数据库 | HTTP、JSON、Qt Network、SQL | 端到端联网闭环 |
| 0.3 系统设计 | 需求、ER 图、数据库、接口契约 | 数据库建模、OpenAPI、UML | 设计文档、建表脚本 |
| 0.4 用户系统 | 登录、读者管理、角色权限 | QML、认证、密码哈希、CRUD | 用户与权限模块 |
| 0.5 图书系统 | 图书、分类、馆藏副本、查询 | Qt 数据模型、SQL 查询与索引 | 图书管理模块 |
| 0.6 借阅系统 | 借书、还书、续借、借阅记录 | 状态机、数据库事务、并发控制 | 完整借还流程 |
| 0.7 预约系统 | 图书预约、排队、取消 | 预约规则、事务、数据库约束 | 图书预约模块 |
| 0.8 云端交付 | 服务器部署、外网访问 | Linux、SSH、Docker、Nginx、HTTPS | Windows 可联网正式版本 |

**阶段验收：** 基础业务闭环可运行；多用户访问同一服务器；角色权限正确；数据库状态一致；系统可独立部署与演示。

### P1：教师推荐进阶功能

| 模块 | 功能任务 | 需要学习的技术 | 交付成果 |
|---|---|---|---|
| Android 构建 | 配置编译环境、真机调试 | Qt for Android、JDK、SDK、NDK、ADB | 可安装 APK |
| 移动端适配 | 手机布局、触摸交互、网络异常处理 | QML Layouts、Qt Network | Android 客户端 |
| 跨端协同 | Windows / Android 共用业务数据 | API、会话管理、并发处理 | 多端一致性验证 |

Android 构建流程：配置 Android 工具链 → 选择 Qt Android Kit → 编译 → 真机调试 → 签名并打包 Release APK。

**阶段验收：** Windows 与 Android 能独立完成核心操作，访问同一服务器，数据正确同步。

### P2：真实场景功能扩展（按难度递增）

| 顺序 | 模块 | 实现内容 | 需要学习的技术 | 难度 |
|---|---|---|---|---|
| 1 | 数据分析 | 热门图书、借阅趋势、馆藏使用率 | SQL 聚合、统计 API、Qt Charts/Graphs | 低 |
| 2 | 消息提醒 | 到期提醒、预约通知、消息中心 | 定时任务、通知表、状态管理 | 低—中 |
| 3 | 智能借阅 | 手机扫码识别图书、自助借还 | Qt Multimedia、ZXing-C++、条码管理 | 中 |
| 4 | 座位预约 | 座位查询、时段预约、签到、超时释放 | 时间区间建模、状态机、并发事务 | 高 |

P2 模块独立设计、逐项交付，不影响 P0/P1 已有功能。

## 四、贯穿全程的工程质量体系

| 领域 | 实施要求 | 技术或产出 |
|---|---|---|
| 架构 | 前后端分离、模块化、接口契约 | Controller / Service / Repository、OpenAPI |
| 代码管理 | 分支开发、代码审查、可回溯提交 | Git、Pull Request |
| 自动化测试 | 单元测试、接口测试、集成测试、回归测试 | GoogleTest、Qt Quick Test、测试脚本 |
| 并发性能 | 模拟多用户、压力测试、业务冲突测试 | k6、并发脚本、压测报告 |
| 安全性 | 身份认证、权限隔离、密码哈希、输入校验 | HTTPS、参数化 SQL、权限测试 |
| 数据安全 | 事务一致性、数据库备份与恢复 | MySQL 事务、备份脚本 |
| 日志审计 | 请求日志、错误日志、关键业务操作记录 | Drogon Logger、操作审计表 |
| 持续集成 | 自动编译、运行测试、保存结果 | CMake、CTest、GitHub Actions |
| 文档 | 需求、架构、接口、数据库、部署及测试记录 | Markdown、OpenAPI、UML |

**实施规则：**
- P0 建立最小可用的测试、安全、日志及部署机制。
- 每新增业务模块，同步补充测试用例、日志和文档。
- P1 开展跨设备和多用户验证。
- P2 针对新增业务进行专项测试。
- 最终进行综合安全、压力、并发、恢复和回归测试，保留完整记录。
- AI Agent 可以辅助生成模拟用户脚本和检查测试覆盖，但核心业务代码由组员自主完成。

## 五、交付与验收标准

| 阶段 | 必须交付 |
|---|---|
| P0 | Windows 客户端、联网后端、MySQL 数据库、基础业务、源码、部署与测试记录 |
| P1 | Android APK、跨端联调及测试报告 |
| P2 | 各扩展模块、对应 API、测试及使用文档 |
| 最终验收 | 稳定运行的软件、自动化测试及压测报告、项目开发报告、至少两次组会纪要 |

**总体原则：功能分阶段扩展，联网架构从 P0 建立；各阶段均交付可运行、可测试、可部署、可追溯的版本。**
