## 一、项目定位

以**真实图书馆可投入使用的工程标准**开发系统，而非仅满足课程演示。采用分阶段、渐进扩展的开发策略：**先完成课程基础要求，再实现教师推荐的进阶功能，最后拓展真实业务场景。**

从第一阶段就建立网络化架构、工程规范和可扩展机制，避免后期推倒重构。

## 二、技术架构

采用 **C++ 全栈、客户端—服务端架构**。

|层次|技术方案|
|---|---|
|桌面与 Android 客户端|Qt 6 + C++ + QML|
|业务后端|C++ + Drogon|
|前后端通信|HTTPS + REST API + JSON|
|数据库|MySQL|
|服务器部署|Linux + Docker + Nginx|
|工程管理|Git + GitHub + CI/CD|
|测试体系|Qt Test、GoogleTest、API 自动化测试、k6 压力测试|

所有客户端通过服务器访问统一的业务系统，不直接连接数据库。

## 三、功能建设优先级

### P0：课程基础要求（必须首先完成）

满足教师明确规定的 Qt、数据库、读者端与后台管理、期末演示及完整开发报告要求。

核心业务以参考项目计划书为依据：

- 读者端：登录、图书查询、借阅、归还、续借、预约、个人借阅记录。
    
- 管理端：图书及馆藏管理、读者管理、借还管理、用户权限管理。
    
- 数据层：完整的关系数据库设计、业务状态管理与数据持久化。
    

上述具体功能作为项目自定的基础交付范围，不全部等同于教师逐项规定的强制功能。

### P1：教师推荐的进阶项（优先加分）

- **网络化**：多用户、多设备同时访问，实时数据同步。
    
- **Android 客户端**：适配移动设备，提供可安装的 APK。
    
- 跨平台适配与可靠的服务器部署。
    

网络化虽属于进阶项，但**从项目初期直接纳入基础架构**，不作为后期补丁。

### P2：真实图书馆场景（业务扩展）

- **智能借阅**：扫码借还、图书识别、自助借阅。
    
- **座位管理**：座位查询、预约、签到、释放。
    
- **数据分析**：热门图书、借阅趋势、馆藏使用率、座位使用率。
    
- **实用服务**：预约排队、到期提醒、逾期管理、消息通知。
    

各模块按独立业务边界设计，按需逐步接入。

## 四、贯穿全程的工程质量要求

工程质量不属于最后才添加的功能，而是贯穿各阶段的基础标准。

|维度|建设目标|
|---|---|
|架构|模块化、分层设计、低耦合、接口稳定|
|测试|单元测试、集成测试、端到端测试、回归测试|
|自动化|脚本或 AI Agent 模拟真实用户操作，验证完整业务流程|
|并发性能|模拟多用户借阅、预约、查询；压力测试、峰值测试、并发冲突验证|
|安全性|身份认证、权限隔离、密码安全存储、输入校验、HTTPS|
|数据可靠性|数据库事务、并发一致性、备份与恢复|
|可观测性|运行日志、错误日志、操作审计、性能指标|
|质量追踪|测试用例、测试报告、缺陷记录、修复记录、版本记录|
|工程协作|Git 分支管理、代码审查、自动构建与测试|
|交付|部署文档、接口文档、用户手册、可复现部署|

性能目标应通过实际压测确定，不预先承诺未经验证的并发能力。

## 五、总体开发策略

**阶段一：工程基础 + 核心业务**

搭建联网架构、服务器、数据库、工程规范及自动化测试基础设施；完成 P0 业务闭环。

**阶段二：平台扩展**

实现 Android 端、多设备访问，完善网络化功能，完成 P1。

**阶段三：真实场景扩展**

逐步实现智能借阅、座位预约、数据分析及其他 P2 功能。

**阶段四：工程验收与优化**

完善全链路测试、安全测试、高并发压力测试、缺陷修复、文档及最终演示。

各阶段均应形成**可运行、可测试、可部署、有记录的稳定版本**，而不是到最后集中集成。

## 六、核心原则

**功能按优先级渐进扩展，架构按最终形态提前规划，工程质量从第一天开始建设。**

不因追求加分功能而牺牲基础业务的完整性，也不因当前功能简单而放弃必要的扩展接口与工程规范。
